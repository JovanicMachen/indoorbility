# Xcode warning corrections

The reported warnings exposed different issues; they do not by themselves prove the cause of all observed navigation lag.

- `GoogleWalkingNavigation`: the Objective-C listener has a nonisolated requirement. Its callback now snapshots immutable text/distance/timestamp values and hops to MainActor for published state. Navigator identity and monotonic timestamps reject stopped-session or out-of-order callbacks. No `@preconcurrency` suppression was added. Map creation now uses `GMSMapView(options:)`.
- `NavigationAudioCoordinator`: AVAudioSession configuration/activation, clip decoding, cue synthesis, AVAudioPlayer preparation/play/stop and volume changes now run on the shared `AppAudioWorker` actor, outside MainActor. Six synthesized cue waveforms are cached. Duplicate travel-loop commands do not repeatedly activate the hardware. Thread-safe request generations invalidate pending playback on Stop/Mute, including activation still in progress. Speech recording has a UUID lease: navigation cannot reconfigure the session while that lease is active, and an old release cannot deactivate a newer recording. The optional directional beacon also requests activation through this worker; its small AVAudioEngine scheduling operation remains on its existing UI owner. Bluetooth uses the current `allowBluetoothHFP` name with the same option value.
- `VoiceCommandInput`: session activation and deactivation use that same worker and retain cancellation checks around permission/activation waits. The existing on-device recognizer and audio-engine ownership remain unchanged.
- `FloorSensor`: `planeExtent.width/height` replace deprecated `extent`. The point is inverse-rotated by `rotationOnYAxis` before containment testing, as required by the newer plane representation. Classification, camera-height limits, measured depth/confidence and missing-evidence behavior remain unchanged.

References: [Apple audio activation](https://developer.apple.com/documentation/avfaudio/avaudiosession/setactive(_:options:)), [ARPlaneExtent](https://developer.apple.com/documentation/arkit/arplaneextent), [Google navigator](https://developers.google.com/maps/documentation/navigation/ios-sdk/reference/objc/Classes/GMSNavigator), [Google listener](https://developers.google.com/maps/documentation/navigation/ios-sdk/reference/objc/Protocols/GMSNavigatorListener). Installed SDK headers were also checked; the new completion-handler audio activation APIs require iOS 27 in this SDK. This project keeps its iOS 17 deployment target and performs the compatible synchronous operations on a background actor rather than on the UI thread.

Validation: the signed iPhone build passed without the reported Swift/Google/Bluetooth/ARKit warnings. 198 core tests passed, including cancellation while activation is pending, stale stop rejection and rotated floor footprints. Two simulator UI regressions passed: production guidance simulation with actual clip playback, tracking-loss pause, recovery and mute; and outdoor camera navigation controls. No new physical walking, microphone-recognition or Bluetooth audio-route measurement was made. These changes are not evidence of improved GPS accuracy or a measured device-wide latency improvement. The UI, saved data, routes, Apple default routing and hosted agent are preserved.
